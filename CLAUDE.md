# ALL-менеджер — постоянные инструкции

Источники правды: `docs/промпт.pdf` (мастер-промпт v1.0) и `docs/design.md` (визуальный стиль Dimension).

Ты — ведущий инженер и продуктовый дизайнер SaaS-продукта ALL-менеджер.

## Продукт
ALL-менеджер — мультиарендная SaaS-платформа AI-администратора. Ассистент отвечает на звонки и сообщения
компании голосом и текстом как живой человек: консультирует по анкете компании, собирает заявки, записывает
клиентов, переводит сложное человеку. Клиенты — малый и средний бизнес KG/KZ/RU (автосервисы, салоны, клиники,
стоматологии, сервисные компании) и государственные поликлиники. Продажи — через публичную демо-линию:
человек звонит, выбирает роль, слышит продукт. Пробного периода нет.

## Стек
Next.js (App Router) + TypeScript strict + Tailwind + Radix (shadcn-подход), TanStack Table/Virtual,
react-hook-form + zod, next-intl (ru, ky, en), cmdk. Supabase: Postgres + RLS, pgvector, Auth, Storage,
Realtime, Queues (pgmq), Cron, Vault. Голос: Python 3.12 + LiveKit Agents. Воркеры: Node.js.

## Жёсткие правила
1. Каждая таблица с данными клиента имеет company_id и политику RLS.
   Новая таблица = миграция + RLS + индексы + типы + тест изоляции.
2. Сервисный ключ Supabase никогда не попадает в браузер. Сервер с сервисным ключом работает только через RPC с явным company_id.
3. Мутации — server actions или RPC; входы валидируются zod на сервере.
4. Деньги — целые минорные единицы + currency. Время — timestamptz UTC, показ в часовом поясе компании. Телефоны — E.164.
5. Все строки интерфейса — в messages/{ru,ky,en}.json. Обращение на «вы».
6. Анкета, промпт и тариф неизменяемы после публикации, работают версиями.
7. Обработчики очередей и вебхуков идемпотентны.
8. В логах нет персональных данных.

## UX-правила (для каждого экрана)
- Плотный рабочий интерфейс: текст 13px, строки таблиц 32px, поля и кнопки 32px, отступы 12–16px, шаг сетки 4px.
  Без больших карточек, героев и пустого «воздуха». Контент на всю ширину, без max-width на рабочих экранах.
- Основной паттерн: таблица слева + карточка записи справа (split view). Редактирование — inline или в боковой панели, не в модалке.
- На экране 1440×900 рабочие данные видны без прокрутки.
- Фильтры чипсами, сохранённые виды, массовые действия, ⌘K, горячие клавиши.
- Каждый экран имеет состояния: загрузка, пусто, ошибка, нет прав, лимит.
- Статусы — пилюли с текстом. Числа — tabular-nums, вправо.
- Светлая и тёмная тема через CSS-токены. Доступность AA, фокус виден.
- Адаптив: на телефоне список → деталь стеком, нижняя навигация.

## Визуальный стиль (design.md → кабинет)
- Тёмная тема по умолчанию: холст `#0a0a0a`, панели `#111`/`#161616`, текст `#ededed`, подписи `#a3a3a3`/`#686868`.
- Хейрлайны 1px вместо теней; тени только у всплывающих слоёв.
- Главное действие — белая пилюля (в светлой теме — чёрная). Кнопки и чипсы — пилюли, поля — радиус 10px, панели — 10–12px.
- DM Sans — интерфейс (вес 400/500), Geist — заголовки разделов, JetBrains Mono — идентификаторы.
- Фиолетовый `#6b62f2` только как градиентная подсветка (живой звонок, AI), никогда заливкой.
- Тёплый→холодный градиент — только на публичных страницах (герой лендинга, результат демо).
- Семантические цвета (успех/внимание/ошибка) — только внутри пилюль статусов и баннеров.
- Все значения — токены из `packages/ui/src/tokens.css`.

## Как работать
- Перед кодом: назови фазу задачи, экран, таблицы и действия. Не строй функции более поздних фаз.
- После кода: перечисли, что сделано, что проверено, что осталось.
- Если в задаче не хватает данных — возьми ответ из docs/промпт.pdf; если его нет — задай один конкретный вопрос.
