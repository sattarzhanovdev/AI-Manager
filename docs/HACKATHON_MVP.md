# ALL-менеджер — Hackathon MVP

Публичная демо-среда AI-администратора: жюри входит по email/паролю, тестирует AI-ассистента голосом или текстом,
AI собирает заявку, заявка сохраняется в Supabase и появляется в CRM.

## Что работает в MVP

| Раздел | Что можно сделать | Где хранится |
| --- | --- | --- |
| Вход | Email + пароль (Supabase Auth), сессия в httpOnly-cookie, выход | Supabase Auth |
| Обзор | KPI по заявкам и звонкам, заявки по статусам, последние действия, «Требует внимания» | `leads`, `lead_events`, `calls` |
| Звонки | 10 исторических демо-звонков с расшифровкой (помечены «[Демо]»), оценка, «перезвонил» | `calls`, `call_turns` |
| Заявки | Канбан/таблица, создание, карточка, статус, ответственный, комментарии, история, фильтры, поиск, источник | `leads`, `lead_events` |
| Контакты | Список, создание, редактирование, связанные заявки и история | `contacts` |
| Анкета (база знаний) | Поля компании, услуги и цены, сотрудники, FAQ, публикация версии | `questionnaires`, `services`, `staff`, `faq`, `kb_snapshots` |
| Ассистент | Настройки (имя, приветствие, режим), **«Протестировать AI»** голосом и текстом | `assistant_settings`, `conversations`, `messages`, `ai_requests` |
| Аналитика | Воронка, нагрузка по часам, передачи — по реальным данным | `calls`, `leads` |

Разделы **Чаты, Календарь, Каналы и интеграции, Команда, Тариф, Настройки, суперадминка** в MVP не подключены к базе:
они скрыты из навигации и по прямой ссылке показывают «Раздел недоступен в демо-версии». Вебхуки каналов в режиме
`DATA_SOURCE=supabase` отвечают 404. В кабинете видна метка **Demo Environment**.

## Главный сценарий (end-to-end)

1. Клиент: «Здравствуйте, сколько стоит замена масла?» → AI отвечает ценой из опубликованной базы знаний (1 500 сом).
2. Клиент: «Хочу записаться на завтра» → AI уточняет имя и телефон.
3. Клиент: «Меня зовут Азамат, мой номер +996 555 123 456» → сервер:
   - находит или создаёт контакт по телефону (E.164),
   - создаёт заявку `booking` с услугой, желаемым временем («завтра») и датой в часовом поясе компании,
   - связывает заявку с диалогом (`leads.source = 'chat'`, `source_id = conversations.id`),
   - возвращает номер заявки; в интерфейсе — ссылка «Заявка №N создана · Открыть в CRM».
4. AI говорит, что это **заявка, а не подтверждённая запись**: календаря в MVP нет, время подтверждает администратор.

Проверено автотестом `apps/web/e2e/mvp.spec.ts` (сценарий 5–6) с прямой проверкой строк в базе.

## Как устроен AI

- Ход диалога — server action `assistantMessage` → `lib/ai/turn.ts`. Ключ LLM только на сервере.
- Ответ строится по **последней опубликованной** версии базы знаний (`kb_snapshots`). Тест черновика — в «Анкете» («Как ответит AI»), он заявки не создаёт.
- **Внешняя LLM** (если задан `ANTHROPIC_API_KEY` или `OPENAI_API_KEY`): системный промпт `@all/dialog` + факты компании + правила веб-демо, функции `search_kb`, `get_service`, `get_hours`, `create_lead`, `transfer_to_human`, `end_call` выполняются на сервере. Цены LLM получает готовой строкой; охрана ответа (`guardText`) заменяет цену, которой нет в базе.
- **Без ключа** — локальный движок `respondOffline` по шаблонам. Метка в интерфейсе: «Локальный движок · ограниченный режим». Если внешняя LLM недоступна, ход отвечает локальный движок, и это тоже видно.
- Сложный запрос («позовите администратора», жалоба, скидка/возврат) → срочная заявка на перезвон; без телефона AI сначала его спрашивает.
- Диалог и его состояние хранятся в `conversations.dialog_state` / `messages` — не в памяти процесса.
- Ограничения: `ai_begin_request` атомарно проверяет запросы пользователя в минуту, запросы компании в день и дневной бюджет токенов (env `AI_*`).

## Голосовое демо

`components/assistant/test-call.tsx`: кнопка «Начать голосовой разговор» → запрос микрофона (`getUserMedia`) →
Web Speech API (распознавание `ru-RU`) → серверный ход → озвучка `speechSynthesis`. Пока AI говорит, микрофон на паузе
(ассистент не слышит сам себя). Ошибки микрофона и неподдерживаемый браузер показываются текстом; ввод текстом доступен всегда.
Работает по HTTPS в Chrome, Edge и Safari. **Это не телефония и не SIP.**

## Безопасность

- RLS на всех таблицах с `company_id`; права проверяются по `memberships` (`is_member`/`has_role` — SECURITY DEFINER), JWT-хук не обязателен.
- `platform_role` нельзя выставить себе через API (триггер); сервисные RPC (`resolve_number`, `get_snapshot`, `check_limits`, `clone_questionnaire_draft`) закрыты от `anon`/`authenticated`.
- `erase_contact`, `book_slot`, `create_lead` проверяют, что объекты принадлежат компании.
- История заявок пишется триггером в базе; автора события подделать нельзя.
- Сервисный ключ используется только provisioning-скриптом; в браузер не попадает (`server-only`).
- Все входы server actions валидируются zod; ошибки базы не показываются пользователю (код запроса для поддержки).
- Mock-вход (код 000000, переключатель ролей) работает только при локальной разработке.

## Тестовые данные

`pnpm --filter @all/web provision:demo` создаёт компанию **AutoCity Service** (автосервис, Бишкек): 2 пользователя
(Demo Owner — собственник, Demo Staff — сотрудник), 2 филиала, 6 сотрудников, 10 услуг с ценами, 15 FAQ, график работы,
настройки ассистента, 20 контактов, 15 заявок в разных статусах, 10 демо-звонков. Все данные вымышленные.
Скрипт идемпотентен и не перезаписывает изменения из кабинета.
