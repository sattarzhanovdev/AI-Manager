# Оставшиеся ограничения и следующие шаги

## Не сделано в рамках Hackathon MVP (осознанно)
- **Телефония** (SIP, номера, LiveKit) — голос только в браузере. `apps/voice` в репозитории, не запускается в MVP.
- **Воркеры очередей** (`apps/workers`): RPC кладут события в pgmq (`lead_created`, `kb_published`), но обработчик не развёрнут — уведомления в Telegram, индексатор эмбеддингов, пост-обработка звонков не работают.
- **Календарь и бронирование**: AI создаёт только заявку на запись, время подтверждает администратор.
- **Чаты (WhatsApp/Telegram/виджет), интеграции, команда/приглашения, биллинг, настройки, суперадминка** — экраны есть, но работают только на mock-данных; в MVP скрыты и закрыты заглушкой, вебхуки отключены.
- **Realtime**: обновление при переходах и после действий; подписка Supabase Realtime в браузере не подключена.
- **Откат версии базы знаний** в MVP выключен (RPC `rollback_questionnaire` конфликтует с нумерацией черновика — нужна доработка).
- **Объединение дублей контактов** в MVP выключено (нет RPC для атомарного переноса связей).
- **Восстановление пароля и регистрация** закрыты; аккаунты создаёт provisioning-скрипт.
- **Английская локализация** не переведена — выбор языка скрыт. Кыргызский переведён для ключевых экранов (навигация, статусы, обзор, заявки, контакты, звонки, ассистент, анкета, аналитика); тексты чатов/календаря/настроек — на русском.
- Описания голосов в настройках ассистента («тёплый женский») и подписи браузерной озвучки — без перевода; голос в браузере — системный голос ОС.

## Известные риски
- Без ключа LLM ассистент работает на шаблонном движке: понимает типовые фразы (цены, график, адрес, запись, жалоба), но хуже ведёт свободный диалог. Режим всегда виден в интерфейсе.
- Распознавание речи Web Speech API в Chrome отправляет звук на сервера Google — для продакшена нужен свой STT.
- Лимиты AI считаются по `ai_requests`; таблица растёт — нужна периодическая очистка/партиционирование.
- `profiles.email` хранится для отображения имени коллег; персональные данные клиентов в логах не пишутся (только коды ошибок и request_id).

## Как проверено
- Миграции на чистом Postgres 16 + pgvector + pgTAP через шим Supabase (`packages/db/scripts/check-migrations.sh`), 36 pgTAP-проверок.
- E2E 10 сценариев против Postgres + PostgREST + совместимого Auth (локально), включая production-сборку.
- LLM-ветка проверена против OpenAI-совместимого тестового сервера (вызовы `get_service`, `create_lead`, `search_kb`, учёт токенов). С настоящим ключом Anthropic/OpenAI не проверялась — ключа не было.
- Настоящий `supabase db reset` / `supabase test db` и e2e на локальном Supabase выполняются в GitHub Actions (job `db`, `e2e`).

## Следующие шаги к production
1. Supabase Cloud: Pro, PITR-бэкапы, staging + prod, миграции через CI.
2. LLM-ключ, мониторинг стоимости и качества (Langfuse, eval на настоящей модели), лимиты под тарифы.
3. Воркеры pgmq (уведомления, эмбеддинги), Supabase Realtime в кабинете.
4. Телефония: LiveKit SIP + `apps/voice`, номера операторов KG/KZ.
5. Календарь и бронирование (`book_slot` с exclusion constraint уже есть).
6. Подключить к базе: команду и приглашения, настройки, интеграции, биллинг.
7. Sentry, алерты, SLA-дашборды; политика ПДн, согласия, DPA.
